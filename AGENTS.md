# Правила для агента — Independent PiP

## Цель проекта
Улучшенный PiP для desktop Chrome без сборки и сторонних runtime-зависимостей. Исходный HTMLVideoElement и его аудио остаются у сайта; расширение показывает muted video-only зеркало и управляет исходным видео. Не превращай проект в универсальную медиаплатформу без отдельной задачи.

## Подход к разработке
Используем лёгкий evidence-first процесс, близкий по смыслу к Proof-Driven Development, а не отдельный PDD-фреймворк. Термин PDD неоднозначен; важны правила ниже, а не название.

1. Сформулируй цель и проверяемые критерии приёмки. Отделяй обязательное поведение от идей в TODO.
2. Прочитай актуальные файлы, определения и вызовы. Проверь git status; не затирай чужие изменения.
3. Для бага сначала воспроизведи конкретный симптом и сохрани падающий тест. Для поведения — RED → GREEN → проверка регрессий. Не маскируй ошибку общим catch или новой архитектурой.
4. Делай минимальный вертикальный срез. Рефакторинг выполняй отдельно от исправления, сохраняя уже проверенное поведение.
5. Проверяй реальную границу: unit-тест с заглушкой Chrome API не доказывает работу Chrome, а headless не доказывает физическое поведение окон Windows.
6. Сохраняй реальные результаты и SHA-256. Не обновляй хеши только ради зелёного CI.
7. Готово = критерии приёмки выполнены и проверены. В отчёте разделяй сделанное, доказанное и непроверенное.

## Архитектура: модульный монолит по функциям
DDD здесь избыточен: сложной предметной модели, агрегатов и независимых bounded contexts пока нет. Не добавляй repository/entity/service-слои лишь ради названий. Сборщик, DI-контейнер, фреймворк и npm runtime не нужны.

- `extension/background.js` — только сборка зависимостей и регистрация событий MV3.
- `extension/protocol.js` — общий контракт сообщений, валидаторы и порядок инъекции. Без побочных эффектов Chrome API.
- `extension/background/windows.js` — привязка только своего PiP-окна, nonce/gesture/sequence, session storage и очередь перемещения.
- `extension/background/discovery.js` — поиск видео на вкладках: разрешения, bounded concurrency, deadlines и частичный результат.
- `extension/background/playback.js` — запуск/закрытие PiP и явное открытие chooser; чувствителен к user activation.
- `extension/background/messages.js` — единственный синхронный message router с явным ответом для каждой принятой команды.
- `extension/background/menus.js` — только пункты ПКМ на значке: настройки и выбор видео.
- `extension/media.js` — обнаружение допустимых исходных video, WeakMap UUID, без запуска воспроизведения.
- `extension/pip.js` — оркестрация захвата, source controls, обновления и lifecycle.
- `extension/pip-view.js` — создание DOM/стилей; не открывает окна и не меняет playback источника.
- `extension/pip-drag.js` — pointer-жесты, frame-aligned coalescing и cleanup; не выбирает чужие окна.
- `extension/picker-client.js` — транспорт chooser; `picker.js` — только представление и пользовательские события.
- `settings.js` / `options.*` — нормализация настроек и отдельная страница настроек.

Модули — IIFE с замороженным namespace и явными параметрами/результатами. Изолируй внутреннее состояние, не создавай ambient globals и циклические зависимости. Namespace в ISOLATED world не является доступным странице API. Карта потоков — `docs/architecture.md`.

## Контракты и важные ограничения
- Toolbar / hotkey: играющее видео → PiP, повторный вызов → закрытие; без подходящего видео → chooser. ПКМ → «Выбор видео» всегда открывает chooser, не закрывая уже работающий PiP.
- Прокидывай выбор видео до первого await, Promise.then или tabs.get: иначе теряется transient user activation. Не повторяй автоматически select/open/toggle.
- Список видео — идемпотентная операция: допускается один повтор после закрытия канала service worker. Поиск ограничен по времени на вкладку и целиком; одна зависшая вкладка не блокирует остальные. Частичный список обозначается явно.
- Принятый runtime message должен завершиться `{ok:true,...}` или `{ok:false,message}`; неизвестное сообщение возвращает false, без обещания ответа. Проверяй sender.id, URL picker и форму идентификаторов.
- Не включай постоянный keepalive для worker. Durable bindings — в `storage.session`, пользовательские настройки — в `storage.local`.
- Не отсоединяй исходный video, не копируй его src во второй декодер, не перезапускай звук. На закрытии очищай только свои tracks/listeners/timers/observers.
- Не обходи DRM, disablePictureInPicture, Permissions-Policy, cross-origin iframe и closed shadow roots. Native fallback не обещает custom controls/captions.
- Подписи страницы/субтитры вставляй как текст, не HTML. DOM-субтитры сайтов и интеграция VOT — отдельные задачи, не выдавай их за поддержку TextTrack/VTT.
- Required permissions: activeTab, scripting, storage, contextMenus. Последнее нужно лишь для ПКМ на значке; не добавляй контекстное меню на страницы сайтов. HTTP/HTTPS host access остаётся optional, после явного согласия.

## Проверка и выпуск
Команды запуска и безопасный браузерный стенд описаны в `docs/development.md`. Основные проверки: Node unit tests, Python ownership tests и `python tools/verify.py` в принадлежащем стенду Chrome. Проверяй JS рекурсивно, включая `extension/background/`.

Не используй обычный профиль пользователя для интеграционных тестов; не закрывай чужие процессы и не захватывай фокус без разрешения. Перед любыми изменениями в тестовом браузере проверяй точный WebSocket endpoint и live profile/debug arguments.

Коммит/публикация — только в разрешённом пользователем объёме, после независимого ревью и exact-head CI. Проверяй извлечённый релизный архив, а не только исходники. Репозиторий и установленное расширение — разные папки: перемещение checkout само по себе не обновляет Chrome. На обновлении установленный путь сохраняется; сначала проверенный rollback, затем замена runtime с manifest последним, readback всех хешей, отдельно Reload и проверка running version. Не объявляй активацию успешной по файлам на диске.
